# Service accounts

A ServiceAccount is an application-scoped identity on the Controller. The identity is the pair `(applicationName, metadata.name)`. It is not a cluster-wide name.

`metadata.applicationName` is required. It must match an [Application](/learn/workloads/applications) `metadata.name`. `roleRef` sits at the document root and names the [Role](/learn/access-control/roles). It is not a field of `spec`.

Fields are on [ServiceAccount fields](/reference/yaml/service-account).

Human Console and API access uses a [RoleBinding](/learn/access-control/role-bindings) with a User or Group subject. A binding can also name this account. The subject `name` on that binding is `metadata.name`, not `application/name`.

The microservice sets `spec.serviceAccount.roleRef` to the Role. See [Microservices](/learn/workloads/microservices) and the field on [Microservice fields](/reference/yaml/microservice#service-account).

Deploy Role, then RoleBinding, then ServiceAccount, then the microservice. Inside one file, the CLI sorts kinds in that order. Deploy the Application first when that name is not already on the Controller.

## Deploy

<CliBlock>{`{{CLI_NAME}} deploy -f serviceaccount.yaml -n my-ecn
{{CLI_NAME}} get serviceaccounts -n my-ecn
{{CLI_NAME}} describe serviceaccount my-app/worker -n my-ecn
{{CLI_NAME}} delete serviceaccount my-app/worker -n my-ecn`}</CliBlock>

<Link to={`/${CLI_DOCS_DIR}/${CLI_NAME}_deploy`}>deploy</Link> creates the account when the pair is missing. The same pair replaces `roleRef`. There is no `apply`.

`describe` and `delete` use `APP/NAME`. `get serviceaccounts` lists the application, the name, and the role.

An empty `metadata.applicationName` is rejected. `metadata.namespace` is the <CliName /> namespace (`-n`).

<Link to={`/${CLI_DOCS_DIR}/${CLI_NAME}_describe_serviceaccount`}>describe serviceaccount</Link> prints `applicationName` on metadata and `roleRef` at the document root. <Link to={`/${CLI_DOCS_DIR}/${CLI_NAME}_delete_serviceaccount`}>delete serviceaccount</Link> takes `APP/NAME`.

## Example

<FlavorYaml title="serviceaccount.yaml">

```yaml
apiVersion: {{API_VERSION}}
kind: ServiceAccount
metadata:
  name: worker
  namespace: my-ecn
  applicationName: my-app
roleRef:
  kind: Role
  name: app-worker
```

</FlavorYaml>

The Role `app-worker` should already exist. A full Role, binding, and account file is on [Access control](/learn/access-control).
