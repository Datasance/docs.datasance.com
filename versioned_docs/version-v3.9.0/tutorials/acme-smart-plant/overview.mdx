# Acme Smart Plant

This example is the plant floor. It does not include fab vision. Vision is [Edge AI wafer defect](/tutorials/edge-ai-wafer-defect).

Four machines (`M001` through `M004`) publish telemetry on **site-a**. Operators on **ops-b** see fleet charts, live alerts, and an event journal. When a fault is open, the dashboard calls **diagnostic-service** on **site-a** through the Router.

Default Edgelet node names are **site-a** and **ops-b**. You can change `agent.name`.

<span id="demo-image-version-v110"></span>

Service images are `ghcr.io/datasance/pot-edge-patterns/<service>:1.2.0`. Use that tag for every service in this example.

Manifests are in [pot-edge-patterns](https://github.com/Datasance/pot-edge-patterns) under `deploy/steps/`. Deploy from that repo root:

<CliBlock>{`{{CLI_NAME}} deploy -f deploy/steps/<file>.yaml`}</CliBlock>

## Topology

```mermaid
flowchart LR
  subgraph siteA [site-a]
    sensor[sensor-simulator]
    detector[smart-anomaly-detector]
    diag[diagnostic-service]
  end
  subgraph opsB [ops-b]
    dash[alert-dashboard]
  end
  sensor -->|telemetry.machine.>| detector
  detector -->|notify.alerts.>| dash
  detector -->|journal.events.>| dash
  dash -->|Router HTTP| diag
```

## NATS subjects {#nats-subjects-and-cross-account-rules}

| Subject | Path |
| --- | --- |
| `telemetry.machine.>` | sensor-simulator to smart-anomaly-detector, then exported for fleet charts |
| `notify.alerts.>` | Live alerts from the detector to the dashboard |
| `journal.events.>` | The same alert kept in JetStream stream `JOURNAL_PRODUCTION` |

The plant account exports those three trees. The operations account imports them. Raw telemetry stays in the plant account until that export exists.
