# Configuration

These pages are the rest of the Config group: data the cluster stores, and the runtime classes Edgelet nodes can run. Every list has Search and the YAML dropzone. Click the name to open the detail panel. There is no Create button. Upload YAML to add a record.


| Page | Sidebar title | Address | Page heading | Deep link |
| --- | --- | --- | --- | --- |
| Config Maps | Config Maps | `/#/config/ConfigMaps` | Config Maps List | `configMapName` |
| Secrets | Secrets | `/#/config/secret` | Secrets | `secretName` |
| Certificates | Certificates | `/#/config/certificates` | Certificates | `name` |
| Volume Mounts | Volume Mounts | `/#/config/VolumeMounts` | Volume Mount List | `volumeMountName` |
| Runtime Classes | Runtime Classes | `/#/config/RuntimeClasses` | Runtime Classes | `runtimeClassName` |

Volume mounts, models, knowledge, and runtime classes share the attach pattern. The detail panel lists **Linked Fog Nodes**, and <ConsoleIcon name="attach" label="Attach" /> **Attach** / <ConsoleIcon name="detach" label="Detach" /> **Detach** change that list.

## Config Maps

![Config maps](/images/docs/edgeops-console/config-configmaps.png)

Named configuration documents. Volume mounts can project a config map onto an Edgelet node, and microservices can consume that mount. How a config map is declared: [Config, secrets, and volumes](/get-started/workloads/config).

| Column | What it shows |
| --- | --- |
| Name | Config map name. Click to open the detail panel. |
| immutable | `true` or `false` |

**Config Map Details:** **Name**, **Immutable**, **Use Vault**.

**Data:** one YAML editor per key. The key is the heading. After you edit a key, a pencil saves that key. <ConsoleIcon name="delete" label="Delete" /> deletes that key. This is separate from the header pencil, which edits the whole config map.

There are no outbound links in this panel. Volume mounts link here.

**Data:** each material key, with reveal and copy.

## Volume Mounts

![Volume mounts](/images/docs/edgeops-console/config-volume-mounts.png)

A volume mount binds a secret or a config map to Edgelet nodes so microservices on those nodes can mount it. See [Config, secrets, and volumes](/get-started/workloads/config).

| Column | What it shows |
| --- | --- |
| Name | Volume mount name. Click to open the detail panel. |
| Secret Name | Secret, when this mount carries a secret |
| ConfigMap Name | Config map, when this mount carries a config map |
| version | Version |

## Runtime Classes

![Runtime classes](/images/docs/edgeops-console/config-runtime-classes.png)

A runtime class names a handler an Edgelet node can use. Microservices pin a runtime by this name. Attach is limited to Edgelet nodes whose container engine is Edgelet. How a runtime class is declared: [Runtime classes](/learn/config/runtime-classes).

| --- | --- |
| Name | Runtime class name. Click to open the detail panel. |
