# Operator

The operator image is <code>{REGISTRY}/operator:3.9.0</code>. On Kubernetes it reconciles `ControlPlane` custom resources. It needs Kubernetes **1.22+**. The only custom resource is `ControlPlane`.

Application workloads are not operator objects. After the control plane is up, create them with <CliName />, the REST API, EdgeOps Console, or the [Go SDK](/learn/platform-components/sdk).

<FlavorYaml title="Operator image">

```yaml
spec:
  images:
    operator: {{REGISTRY}}/operator:3.9.0
```

</FlavorYaml>

## Removed in v3.8

v3.8 removed the Application CRD, Keycloak fields, and ECN Viewer fields. The operator watches `ControlPlane` only.

Platform train **v3.9.0** supports an in-place upgrade from **v3.8.0**. Follow [Upgrading to v3.9.0](/release-notes/upgrading-to-v3-9).

There is no direct upgrade from v3.7. Move to v3.8.0 first. See [Migrating to v3.8.0](/release-notes/migrating-to-v3-8).

## Helm

Charts publish to each mirror's gh-pages index. The legacy standalone repo [Datasance/helm](https://github.com/Datasance/helm) is deprecated.

<CliBlock title="Add the Helm repository">{`helm repo add iofog-operator ${FLAVOR === 'datasance' ? 'https://datasance.github.io/iofog-operator' : 'https://eclipse-iofog.github.io/iofog-operator'}
helm repo update`}</CliBlock>

<CliBlock title="Install the operator">{`helm install iofog-operator iofog-operator/iofog-operator \\
  --namespace iofog-system --create-namespace \\
  --version 3.9.0`}</CliBlock>

For a full control plane install, see [Kubernetes Helm deployment](/get-started/deploy/kubernetes-helm).

## Manifest tarball

GitHub Releases attach `manifests-iofog-<version>.tar.gz` and `manifests-datasance-<version>.tar.gz`. Apply them in namespace `iofog-system`.

<CliBlock>{`VERSION=3.9.0
FLAVOR=${FLAVOR === 'datasance' ? 'datasance' : 'iofog'}

curl -fsSL -o manifests.tar.gz \\
  "https://github.com/eclipse-iofog/iofog-operator/releases/download/v\${VERSION}/manifests-\${FLAVOR}-\${VERSION}.tar.gz"
tar xzf manifests.tar.gz
kubectl apply -f "manifests-\${FLAVOR}-\${VERSION}/crds/"
kubectl apply -f "manifests-\${FLAVOR}-\${VERSION}/operator/install.yaml"`}</CliBlock>

Adapt and apply the sample ControlPlane from the tarball for your cluster.

## OLM

Package `iofog-operator`, channel `stable`, namespace `iofog-system`.

<CliBlock>{`VERSION=3.9.0

operator-sdk run bundle "{{REGISTRY}}/operator-bundle:\${VERSION}" \\
  --namespace iofog-system --timeout 5m`}</CliBlock>
