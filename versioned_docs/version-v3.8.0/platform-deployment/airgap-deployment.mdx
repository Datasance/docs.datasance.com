# Airgap Deployment

This page describes how to deploy and run Datasance PoT in **air-gapped** or **restricted networks** where remote Control Plane hosts or Edgelet node hosts cannot access the internet (or container registries) directly.

## Overview

<code>{CLI_NAME}</code> allows users to deploy container images to edge nodes that cannot access the internet for pulling images. Set `spec.airgap: true` on Control Plane or **`Agent`** (Edgelet node) YAML. <code>{CLI_NAME}</code> pulls images on your workstation, transfers them over SSH, and loads them on the remote host.

:::warning
For airgap installations <code>{CLI_NAME}</code> assumes that your remote hosts already have a container engine.
:::

## Remote ControlPlane

<FlavorYaml>{`---
apiVersion: {{API_VERSION}}
kind: ControlPlane
metadata:
  name: remote
spec:
  airgap: true
  iofogUser:
    name: Foo
    surname: Bar
    email: mail@example.com
  controller:
    publicUrl: https://controller.example.com:51121
    consoleUrl: https://console.example.com:8008
    package:
      image: {{REGISTRY}}/controller:v3.8.0
  auth:
    mode: embedded
    bootstrap:
      username: admin
      password: "LocalTest12!"
  systemMicroservices:
    router:
      amd64: {{REGISTRY}}/router:3.8.0
      arm64: {{REGISTRY}}/router:3.8.0
      riscv64: {{REGISTRY}}/router:3.8.0
      arm: {{REGISTRY}}/router:3.8.0
    nats:
      amd64: {{REGISTRY}}/nats:2.14.3
      arm64: {{REGISTRY}}/nats:2.14.3
      riscv64: {{REGISTRY}}/nats:2.14.3
      arm: {{REGISTRY}}/nats:2.14.3
  nats:
    enabled: true
  controllers:
    - name: remote-1
      host: 10.0.23.66
      ssh:
        user: admin
        keyFile: ~/.ssh/id_rsa
      systemAgent:
        package:
          container:
            image: {{REGISTRY}}/edgelet:1.0.0
        config:
          deploymentType: container
          containerEngine: docker
          arch: amd64
          host: 192.168.139.148
`}</FlavorYaml>

Set `spec.airgap: true`. <code>{CLI_NAME}</code> downloads Controller, Edgelet, Router, NATS, and debugger images and sends them to the remote host over SSH.

Set `controllers[].systemAgent.config.arch` and `controllers[].systemAgent.config.containerEngine` so <code>{CLI_NAME}</code> knows which Edgelet image to pull and transfer. List all four arch keys under `systemMicroservices` when your fleet mixes CPU types.

Default airgap installation scripts:

- [Airgap Controller scripts](https://github.com/Datasance/potctl/tree/main/assets/airgap-controller)
- [Airgap Edgelet node scripts](https://github.com/Datasance/potctl/tree/main/assets/airgap-agent)

Download and customize these scripts if <code>{CLI_NAME}</code> should use your own install flow.


## Remote Edgelet nodes

<FlavorYaml>{`---
apiVersion: {{API_VERSION}}
kind: Agent
metadata:
  name: foo
spec:
  host: 192.168.139.148
  ssh:
    user: foo
    keyFile: ~/.ssh/id_rsa
    port: 22
  airgap: true
  package:
    container:
      image: {{REGISTRY}}/edgelet:1.0.0
  config:
    deploymentType: container
    containerEngine: docker
    arch: arm64
`}</FlavorYaml>

Set `spec.airgap: true` on the **`Agent`** kind (Edgelet node). <code>{CLI_NAME}</code> downloads Edgelet, Router, NATS, and debugger images and sends them to the remote host over SSH.

Set `spec.config.arch` and `spec.config.containerEngine` so <code>{CLI_NAME}</code> knows which Edgelet image to pull and transfer.


## OfflineImage for microservices

[OfflineImage](../yaml-references/reference-offlineimage) is the main mechanism for getting container images onto Edgelet nodes that cannot pull from the internet. v3.8.0 uses multi-arch keys (`amd64`, `arm64`, `riscv64`, `arm`) instead of legacy `x86` / `arm` fields.

1. On a machine that has registry access (and <code>{CLI_NAME}</code>), define an OfflineImage YAML with image tags per architecture and the list of Edgelet node names.
2. Run <code>{CLI_NAME} deploy -f offline-image.yaml</code>. <code>{CLI_NAME}</code> pulls the images locally, transfers them to each Edgelet node via SSH, and loads them into the container runtime. Catalog items are created with registry `from_cache` so applications can reference these images.
3. Use flags such as `--no-cache` and `--transfer-pool` as needed (see [OfflineImage reference](../yaml-references/reference-offlineimage)).

Example multi-arch bundle:

<FlavorYaml>{`---
apiVersion: {{API_VERSION}}
kind: OfflineImage
metadata:
  name: my-app-offline
spec:
  amd64: {{REGISTRY}}/my-app:1.0
  arm64: {{REGISTRY}}/my-app:1.0
  agent:
    - edge-1
    - edge-2
`}</FlavorYaml>

This flow avoids any need for the Edgelet node to reach a registry. All image data is pushed from the machine running <code>{CLI_NAME}</code> to the nodes over SSH.

For OfflineImage YAML and CLI flags, see [OfflineImage YAML Specification](../yaml-references/reference-offlineimage). For the full deployment path, see [Platform Deployment Introduction](introduction).
