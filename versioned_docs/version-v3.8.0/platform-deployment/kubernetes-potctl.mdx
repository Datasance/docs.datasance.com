# Kubernetes - Deploy Control Plane Using {CLI_NAME}

Every Edge Compute Network ('ECN') starts with a Control Plane that allows us to manage our ECN's resources.

In this guide, our Control Plane will deploy a single Controller instance through the PoT Operator.

:::info[We use YAML to define PoT resources]
  <p>The following procedures will define resources in YAML for {CLI_NAME} to consume. Specification of those YAML resources can be found <a href="../yaml-references/reference-control-plane">here</a>.</p>
:::

## Deploy a Control Plane on Kubernetes

:::info[Authentication]

Set `auth.mode: embedded` in your Control Plane YAML. See [Embedded OIDC Authentication](/platform-deployment/embedded-oidc) for bootstrap credentials and TLS requirements.

:::

:::warning[NATs Replica]
  <p>When NATs is enabled, the minimum replica should be 2 in order to initialize NATs JetStream Cluster.</p>
:::

:::warning[Setup your db for production environment]
{CLI_NAME} supports both `mysql` and `postgres` as external databases.
You must provide external db configuration if you want to deploy `Controller` with replica &gt; 1.
<p>We recommend going through the <a href="../platform-deployment/database">Database Installation Guide</a> before continuing on here.</p>
:::

Create `controlplane.yaml`:

<FlavorYaml title="controlplane.yaml">{`---
apiVersion: {{API_VERSION}}
kind: KubernetesControlPlane
metadata:
  name: albatros-1
spec:
  iofogUser:
    name: Foo
    surname: Bar
    email: user@domain.com
    password: iht234g9afhe
  config: ~/.kube/config
  replicas:
    controller: 1
    nats: 2
  auth:
    mode: embedded
    bootstrap:
      username: admin
      password: LocalTest12!
  controller:
    publicUrl: https://controller.example.com:51121
    consoleUrl: https://console.example.com:8008
  nats:
    enabled: true
    jetStream:
      storageSize: "10Gi"
      memoryStoreSize: "1Gi"
  images:
    operator: {{REGISTRY}}/operator:3.8.0
    controller: {{REGISTRY}}/controller:v3.8.0
    router: {{REGISTRY}}/router:3.8.0
    nats: {{REGISTRY}}/nats:2.14.3
  services:
    controller:
      type: LoadBalancer
    router:
      type: LoadBalancer
    nats:
      type: LoadBalancer
    natsServer:
      type: LoadBalancer
`}</FlavorYaml>

Set `config` to your kubeconfig path. {CLI_NAME} deploys to the namespace from the `-n` flag or your configured default. Use a dedicated namespace instead of `default` in production.

Deploy:

<CliBlock>{`{{CLI_NAME}} deploy -f controlplane.yaml`}</CliBlock>
Check cluster state with `kubectl`:

```bash
kubectl get all
```

## Verify the Deployment

<CliBlock>{`{{CLI_NAME}} get controllers`}</CliBlock>
<CliBlock>{`{{CLI_NAME}} describe controller alpaca-1`}</CliBlock>
<CliBlock>{`{{CLI_NAME}} describe controlplane`}</CliBlock>
For optional database, ingress, vault, and service overrides, see the [Control Plane YAML reference](../yaml-references/reference-control-plane).

:::tip[Where to go from here?]
  <p>With the Control Plane running, go to <a href="../platform-deployment/setup-your-agents">Setup Edgelet nodes</a> to provision Edgelet v1.0.0 on your edge hosts.</p>
:::
