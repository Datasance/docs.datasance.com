# Quick Start With Local Deployment

:::warning[Greenfield release: v3.8.0]

<ProductName /> **v3.8.0** is a greenfield release. There is no in-place upgrade from v3.7 field deployments.

You need a new Controller database, **Edgelet v1.0.0+** on every node, and **<CliName /> v3.8.0**. Legacy Java iofog-agent and v3.7 field agents are not supported on Controller v3.8.

See [Migrating to v3.8.0](/migrating-to-v3-8) for the step-by-step guide.

:::

This guide deploys a minimal local ECN on one machine:

1. **LocalControlPlane** with [embedded OIDC](/platform-deployment/embedded-oidc)
2. A **system Edgelet node** on the same host (via `spec.systemAgent`)
3. A pointer to deploy sample workloads ([Acme Smart Plant Tutorial](/tutorials/acme-smart-plant))

You do **not** deploy a separate **`LocalAgent`**. The system Edgelet is part of the Control Plane YAML. See [Control Plane YAML Specification](/yaml-references/reference-control-plane#local-control-plane).

## Choose your platform

| Platform | Container engine | `containerEngineUrl` | Typical `deploymentType` |
| -------- | ---------------- | -------------------- | ------------------------ |
| **Linux** | `edgelet` | `unix:///run/edgelet/containerd.sock` | `native` |
| **macOS / Windows** | `docker` | `unix:///var/run/docker.sock` | `container` |

Use the manifest and prerequisites for your OS below. Both paths produce the same local ECN: Controller, Router, and system Edgelet on one host.

:::info[Authentication]

**<ProductName /> v3.8.0** uses [embedded OIDC](/platform-deployment/embedded-oidc) by default. You do not need an external IdP for this quick start.

:::

## Linux

### Prerequisites

- **Linux** (amd64, arm64, or another [supported arch](/yaml-references/reference-agent#configuration-fields))
- **<CliName /> v3.8.0** - see the <CliDocsLink path="/download">Download and install <CliName /></CliDocsLink> page
- **sudo** access on the host (<CliName /> installs Edgelet and starts `edgelet.service` during deploy)

Docker is **not** required on this path. The system Edgelet uses the embedded **edgelet** engine and containerd socket.

### Manifest

Save as `quick-start.yaml`:

<FlavorYaml title="quick-start.yaml (Linux)">{`---
apiVersion: {{API_VERSION}}
kind: LocalControlPlane
metadata:
  name: ecn
spec:
  iofogUser:
    name: Quick
    surname: Start
    email: user@domain.com
    password: QuickStartUser12!
  controller:
    publicUrl: http://<your-host-ip>:51121
    consoleUrl: http://<your-host-ip>
    package:
      image: {{REGISTRY}}/controller:v3.8.0
  auth:
    mode: embedded
    insecureAllowHttp: true
    bootstrap:
      username: admin
      password: QuickStart12!
  nats:
    enabled: true
  systemAgent:
    package:
      version: 1.0.0
    config:
      arch: amd64
      deploymentType: native
      containerEngine: edgelet
      containerEngineUrl: unix:///run/edgelet/containerd.sock
`}</FlavorYaml>

Set `systemAgent.config.arch` to match your CPU (`arm64`, `riscv64`, or `arm` on 32-bit ARM hosts).

### Deploy

<CliBlock>{`{{CLI_NAME}} deploy -f quick-start.yaml`}</CliBlock>

Continue with [Verify the deployment](#verify-the-deployment).

## macOS and Windows

### Prerequisites

- **Docker v26.0+** running ([Docker Desktop](https://docs.docker.com/desktop/))
- **<CliName /> v3.8.0** - see the <CliDocsLink path="/download">Download and install <CliName /></CliDocsLink> page

On Windows, use Docker Desktop with **Linux containers** (WSL2 or Hyper-V backend). Run <CliName /> from an environment that can reach the Docker socket (WSL2 is recommended).

### Manifest

Save as `quick-start.yaml`:

<FlavorYaml title="quick-start.yaml (macOS / Windows)">{`---
apiVersion: {{API_VERSION}}
kind: LocalControlPlane
metadata:
  name: ecn
spec:
  iofogUser:
    name: Quick
    surname: Start
    email: user@domain.com
    password: QuickStartUser12!
  controller:
    publicUrl: http://<your-host-ip>:51121
    consoleUrl: http://<your-host-ip>
    package:
      image: {{REGISTRY}}/controller:v3.8.0
  auth:
    mode: embedded
    insecureAllowHttp: true
    bootstrap:
      username: admin
      password: QuickStart12!
  nats:
    enabled: true
  systemAgent:
    package:
      container:
        image: {{REGISTRY}}/edgelet:1.0.0
    config:
      arch: amd64
      deploymentType: container
      containerEngine: docker
      containerEngineUrl: unix:///var/run/docker.sock
`}</FlavorYaml>

### Deploy

<CliBlock>{`{{CLI_NAME}} deploy -f quick-start.yaml`}</CliBlock>

Continue with [Verify the deployment](#verify-the-deployment).

## Verify the deployment

Check <CliName /> resources:

<CliBlock>{`{{CLI_NAME}} get all`}</CliBlock>

Expected output (fields may vary):

```plain
NAMESPACE
default

CONTROLLER      STATUS    AGE           UPTIME      ADDR             PORT
ecn             online    22m29s        22m35s      0.0.0.0          51121

AGENT           STATUS    AGE           UPTIME      ADDR             VERSION
ecn             RUNNING   22m7s         22m7s       192.168.1.10     1.0.0

APPLICATION     STATUS    MICROSERVICES

MICROSERVICE    STATUS    AGENT         ROUTES      VOLUMES          PORTS

VOLUME          SOURCE    DESTINATION   PERMISSIONS   AGENTS

ROUTE           SOURCE MSVC     DEST MSVC
```

The **Controller** row is the control plane API. The **Agent** row named **`ecn`** is the system Edgelet node from `spec.systemAgent` (same name as `metadata.name`).

**Note:** Edgelet node status may show `UNKNOWN` for up to 30 seconds while the node reports liveness to the Controller.

### Linux: Edgelet service

On the native Linux path, confirm Edgelet is running:

<CliBlock>{`edgelet system status`}</CliBlock>

Or:

```bash
systemctl status edgelet
```

List system microservices (Controller, Router) deployed through Edgelet:

<CliBlock>{`edgelet ms ls`}</CliBlock>

### macOS / Windows: Docker containers

On the Docker path, Controller, Router, and Edgelet workloads run as containers:

```bash
docker ps
```

You should see **controller**, **router**, and **edgelet** images from your distribution registry (same prefix as in the YAML above).

See [Edgelet introduction](/edgelet/introduction) and [Control Plane YAML](/yaml-references/reference-control-plane) for field details.
