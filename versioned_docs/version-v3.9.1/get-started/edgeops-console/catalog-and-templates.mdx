# Catalog and templates

These pages live in the Config group. They describe images, models, knowledge, and the templates you deploy from. Every list has Search and the YAML dropzone. None of them has a Create button. You add records by uploading YAML. You deploy a running workload from a template with <ConsoleIcon name="publish" label="Publish" /> **Publish**.

| Page | Sidebar title | Address | Deep link |
| --- | --- | --- | --- |
| Registries | Registries | `/#/config/Registries` | `registryId` |
| Catalog Microservices | Catalog Microservices | `/#/config/CatalogMicroservices` | `catalogItemid` |
| AI Model Catalog | AI Model Catalog | `/#/config/Models` | `modelName` |
| AI Knowledge Catalog | AI Knowledge Catalog | `/#/config/Knowledge` | `knowledgeName` |
| Application Templates | App Templates | `/#/config/AppTemplates` | - |
| Microservice Templates | Microservice Templates | `/#/config/MicroserviceTemplates` | `microserviceTemplateName` |

Click the name (or the URL, on Registries) to open the detail panel.

## Registries

![Registries](/images/docs/edgeops-console/config-registries.png)

Registries hold the credentials and TLS settings used when the cluster pulls images, models, or knowledge. How a registry is declared: [Registries and catalog](/get-started/workloads/registries).

| Column | What it shows |
| --- | --- |
| ID | Registry id |
| URL | Registry URL. Click to open the detail panel. |
| Type | Registry type. An empty type is shown as `oci`. |
| PRIVATE | `true` when the registry is private, `false` when it is public |

## Catalog Microservices

![Catalog list](/images/docs/edgeops-console/config-catalog.png)

A catalog item is a named microservice image, with up to one image per architecture, that templates and workloads can reference. See [Registries and catalog](/get-started/workloads/registries).

## AI Knowledge Catalog

![AI knowledge](/images/docs/edgeops-console/config-knowledge.png)

Same page shape as AI Model Catalog, for knowledge and document bundles. Any container engine can receive a knowledge attachment. The microservice editor mounts it into a user microservice. See [Models and knowledge](/get-started/workloads/models-and-knowledge).

| Column | What it shows |
| --- | --- |
| Name | Knowledge name. Click to open the detail panel. |
| Repo | Repository |
| Registry | Link to Registries |
| Format | Format |

### Knowledge detail panel

Title is the knowledge name. Icons match models: Attach, Detach, Edit, Delete, Close.

Toasts: **Knowledge attached**, **Knowledge detached**. Delete is titled **Deleting Knowledge** plus the name.

**Knowledge Details:** **uuid**, **Name**, **Repo**, **Revision**, **Registry** (link), **Files** (same Hugging Face rule as models), **Format**, and a format hint:

> Known values: markdown, pdf, jsonl, parquet, arrow, sqlite, faiss, chroma, lance. Any other text is stored as unknown. Empty means omitted.

**Linked Fog Nodes** works the same way as on a model. Each node name opens Edgelet List.

Attach and detach dialogs use the same placeholders as models.

### Deploy form

![Application deploy form](/images/docs/edgeops-console/config-app-template-deploy.png)

The drawer title reads **Editing Deploy an application from** the template name **Template**.

- **Application Name**, placeholder **Enter application name**. Help text: *Name for the deployed application instance*. Required.
- Each template variable is a row: the key, its description, and an input.
  - A variable that expects an Edgelet node is a **Select an agent** list of the cluster Edgelet nodes.
  - A boolean variable is **Select**, **true**, or **false**.
  - A read-only variable says **Variable** plus the key **is not configurable**.

**Save** in the drawer asks **Deploy** plus the name: deploy an application from this template. **Cancel** returns to the form. **Deploy** runs it. Success toast: **Application deployed!**. If the name is empty, the form reports **Application name is required**.

### Deploy form

![Microservice deploy form](/images/docs/edgeops-console/config-ms-template-deploy.png)

Drawer title: **Editing Deploy a microservice from** the template name **Template**.

- **Microservice Name**, placeholder **Enter instance name**
- **Application.** **Select an application**, unless a variable already captures the application
- **Agent.** **Select an agent**, unless a variable already captures the Edgelet node
- Remaining variables follow the application-template rules (Edgelet node picker, boolean, read-only)

Deploy stays unavailable until the instance name, application, and Edgelet node are all set. Confirm **Deploy** plus the name. Success toast: **Microservice deployed!**.
