# Deploy Control Plane on Remote Hosts

Use **`kind: ControlPlane`** (not `RemoteControlPlane`) to run the control plane on one or more SSH-accessible hosts via **Edgelet**. Global settings (auth, database, images, TLS) are declared once; each host is listed under **`spec.controllers[]`**.

See the [remote deploy guide](/learn/control-plane/remote) for multi-host orchestration and [multi-controller HA](/learn/control-plane/remote-ha) when you add hosts.

:::info[YAML resources for <CliName />]

Procedures below use YAML that **<CliName />** applies. Field reference: [Remote ControlPlane schema](/reference/yaml/remote-control-plane).

:::

:::info[Authentication]

Set `auth.mode: embedded` in your control plane YAML. See [Embedded OIDC](/get-started/deploy/embedded-oidc) for bootstrap credentials and console URLs.

:::

:::tip[Production TLS]

Enable **Controller HTTPS** with **`spec.tls`** (cert, key, optional ca) or **`controllers[].tls`** per host. For bring-your-own Router and NATS CAs, set the four global CA blocks; the CLI uploads them after the Controller API is up. See [Securing remote control plane](/learn/security/control-plane-remote).

:::

## Prerequisites

- Passwordless **sudo** on remote hosts
- SSH key access: `ssh.user`, `ssh.keyFile`, optional `ssh.port` (default 22)
- **`spec.controllers[].systemAgent`** on every controller (may be `{}` for defaults)
- **`spec.endpoint`** or **`spec.controller.publicUrl`** for API wait and Edgelet configuration

Details: [Prepare remote hosts](/get-started/deploy/prepare-your-remote-hosts).

## Deploy a control plane on a remote host

Create `controlplane.yaml` (single-host example):

<FlavorYaml title="controlplane.yaml">{`---
apiVersion: {{API_VERSION}}
kind: ControlPlane
metadata:
  name: edge-prod
spec:
  endpoint: http://203.0.113.10:51121
  iofogUser:
    email: ops@example.com
    password: "ReplaceMe-password!"
  controller:
    publicUrl: http://203.0.113.10:51121
    consoleUrl: http://203.0.113.10:80
    logLevel: info
    package:
      image: {{REGISTRY}}/controller:v3.9.0
  auth:
    mode: embedded
    bootstrap:
      username: admin
      password: RemoteTest12!
  systemMicroservices:
    router:
      amd64: {{REGISTRY}}/router:3.9.0
      arm64: {{REGISTRY}}/router:3.9.0
      arm: {{REGISTRY}}/router:3.9.0
      riscv64: {{REGISTRY}}/router:3.9.0
    nats:
      amd64: {{REGISTRY}}/nats:2.15.0
      arm64: {{REGISTRY}}/nats:2.15.0
      arm: {{REGISTRY}}/nats:2.15.0
      riscv64: {{REGISTRY}}/nats:2.15.0
  nats:
    enabled: true
  events:
    auditEnabled: true
    retentionDays: 14
  controllers:
    - name: ctrl-1
      host: 203.0.113.10
      ssh:
        user: ubuntu
        keyFile: ~/.ssh/prod.pem
        port: 22
      systemAgent:
        config:
          arch: amd64
          host: 203.0.113.10
`}</FlavorYaml>

Edit `host`, `ssh`, URLs, and architecture keys for your environment.

Deploy:

<CliBlock>{`{{CLI_NAME}} deploy -f controlplane.yaml -n prod`}</CliBlock>

## Verify the deployment

<CliBlock>{`{{CLI_NAME}} get controllers`}</CliBlock>

<CliBlock>{`{{CLI_NAME}} describe controller ctrl-1`}</CliBlock>

<CliBlock>{`{{CLI_NAME}} describe controlplane`}</CliBlock>

:::tip[Add another controller host later?]

You need a **full** remote ControlPlane record in namespace config (includes `auth` and `controller`). Use initial **`deploy -f`** or **`connect -f`** with the same YAML. See [Controller add-on](/learn/control-plane/controller-add-on).

:::
