# OCI registry

## Goal

Create a Registry row for **ghcr.io** with `type: oci`. The wafer-defect ONNX artifact is an OCI blob. Built-in registry `1` (`docker.io`) cannot pull it.

You need an Edgelet node you will call **edge-c**. You can change `agent.name` later if the node has another name.

## YAML

Use a public endpoint when the package is world-readable. Save this as `ghcr-registry.yaml`.

<FlavorYaml title="ghcr-oci">

```yaml
apiVersion: {{API_VERSION}}
kind: Registry
metadata:
  name: ghcr-oci
spec:
  url: ghcr.io
  type: oci
  private: false
```

</FlavorYaml>

For a private package, set `private: true` and add a robot `username` and `password`. See [Registries](/learn/config/registries).

## What you should see

A row with `type: oci` and `url: ghcr.io`. Write down the numeric id. The model page uses it as `spec.registryId`.

## Common mistakes

Using registry `1` on the model. That row does not serve this GHCR artifact.

Leaving out `type: oci`. The catalog expects an OCI layout for this model.
