# What's New in <ProductName />

:::info[Upgrade from v3.9.1, v3.9.0, or v3.8.0]

**v3.9.2** stays on the same Controller database. There is no schema or API change. No Control Plane YAML key was removed.

From **v3.9.1** or **v3.9.0**, bump image tags and roll **Edgelet v1.1.2**. From **v3.8.0**, use the same tags and move straight to **v3.9.2**. You also pick up the v3.9 catalogs and registry fields.

If your external issuer certificate is signed by a private CA, set **`auth.issuerCa`** before you roll the operator. A public CA needs no new field. On Kubernetes, rewrite a saved Helm values file to the flat **3.9.2** keys before `helm upgrade`.

See [Upgrading to v3.9.2](/release-notes/upgrading-to-v3-9). **v3.7.x and older** still move to **v3.8.0** first: [Migrating to v3.8.0](/release-notes/migrating-to-v3-8).

:::

**v3.9.2** is a security patch on the v3.9 train. Pair **Controller v3.9.2**, **{CLI_NAME} v3.9.2**, **Edgelet v1.1.2**, **Operator v3.9.2**, **Router v3.9.2**, and **NATS wrapper 2.15.1-1**. **EdgeOps Console** stays **v1.1.1**.

- [**Platform train v3.9.2**](#platform-train-v392) lists the pins.

- [**Edgelet v1.1.2**](#edgelet-v112) passes **`issuerCa`** into the Controller. No Edgelet API change.
- [**EdgeOps Console**](#edgeops-console) stays **v1.1.1**.
- [**v3.9 features**](#ai-model-and-knowledge-catalogs) (Model and Knowledge catalogs, registry `type`, container fields) still apply when you come from v3.8.0.
- [**Upgrade and migration paths**](#upgrade-and-migration-paths) summarize who can move in place.

## Security patch

Control plane images, <CliName />, the operator, the Router wrapper, Edgelet, the Go SDK, and the NATS wrapper are rebuilt on **Go 1.26.10**. That toolchain clears [GO-2026-6809](https://pkg.go.dev/vuln/GO-2026-6809) (`crypto/x509` distrust of compromised intermediate certificates).

The Controller image is Node.js. This patch does two checks there:

- User exec and log WebSocket upgrades verify the access token (signature, issuer, audience, and expiry) before RBAC. Agent sockets still use the fog token.
- Liquid substitution on `POST`, `PUT`, and `PATCH` runs only after RBAC. The engine refuses template file reads, and it rejects a `range` wider than 10,000 or a render that passes 100,000 `for` iterations.

The operator verifies TLS on Controller API calls and on external issuer login. The minimum version is TLS 1.2. When `controller.https` is set, the certificate must match the `publicUrl` host. The operator still dials the in-cluster Service.

No YAML keys were removed. The new field is optional. The [Controller API](/api/v3.9.0/controller) and [Edgelet API](/api/v1.1.0/edgelet) pages stay on those paths.

## Private issuer CA

External mode can trust an HTTPS issuer signed by a private CA without turning certificate checks off.

Set **`auth.issuerCa`** to the standard base64 of a PEM CA, or of a concatenated PEM bundle. Leave it empty for a public CA. Embedded mode ignores the field.

| Surface | Field | Controller setting |
| ------- | ----- | ------------------ |
| ControlPlane custom resource, Helm `auth.issuerCa`, and <CliName /> YAML | `auth.issuerCa` | `OIDC_ISSUER_TLS_BASE64_CA` |
| Edgelet control-plane manifest | `spec.auth.issuerCa` | `OIDC_ISSUER_TLS_BASE64_CA` |
| Controller config file | `auth.issuer.tls.path.ca` or `auth.issuer.tls.base64.ca` | `OIDC_ISSUER_TLS_PATH_CA` or `OIDC_ISSUER_TLS_BASE64_CA`. Path wins when both are set |

<CliName /> **v3.9.2** passes `issuerCa` on Kubernetes, local, and remote control plane YAML. There are no new CLI commands.

[Find out more!](/get-started/deploy/external-oidc), [Controller configuration](/reference/controller/controller-config), and [Control plane YAML](/reference/yaml/kubernetes-control-plane).

## Helm values

Helm chart **3.9.2** takes a flat values file. `auth`, `images`, `database`, `services`, `controller`, `nats`, `vault`, and `events` are top-level keys. The chart always installs the CRD, RBAC, and one ControlPlane.

`values.schema.json` is removed. `marketplace-values.yaml` is the marketplace form. Do not pass it as a second `-f` file.

A values file from chart 3.9.1 uses `controlplane.spec`. Rewrite it before `helm upgrade`. `services.nats.type` now defaults to **LoadBalancer**. `services.natsServer.type` defaults to **ClusterIP**, so the non-TLS client port is not published. `nats.memoryStoreSize` and `nats.storageSize` are whole numbers of Gi.

[Find out more!](/get-started/deploy/kubernetes-helm).

## AI Model and Knowledge catalogs

v3.9 adds fleet **`kind: Model`** and **`kind: Knowledge`** resources. The Controller pulls weights or datasets from **`type: hf`** or **`type: oci`** [registries](/learn/config/registries), tracks attach state per Edgelet node, and mounts ready content into microservices.

| Catalog | Purpose | Microservice bind |
| ------- | ------- | ----------------- |
| **Model** | LLM and inference weights (GGUF, safetensors, OCI model-spec) | **`spec.models.items[]`** |
| **Knowledge** | RAG corpora, Hub datasets, OCI document bundles | **`spec.knowledge.items[]`** |

Console path: **Config → AI Model Catalog** and **Config → AI Knowledge Catalog**. CLI: **`deploy`**, **`describe model`**, **`attach model`**, and the matching **`knowledge`** commands.

Edgelet nodes can also hold local **`edgelet.iofog.org/v1`** models for lab workflows. Fleet operators usually use the Controller catalog.

[Find out more!](/learn/config/ai-model-catalog), [AI Knowledge Catalog](/learn/config/ai-knowledge-catalog), and [Microservices - models and knowledge](/learn/workloads/microservices#v39-container-models-and-knowledge).

## Registries (OCI and Hugging Face)

Registry rows now declare a backend with **`spec.type`**: **`oci`** (container registries) or **`hf`** (Hugging Face Hub). Private Hub pulls use a token in **`password`**.

v3.9 removes **`requiresCert`**, **`certificate`**, and **`isSecure`**. Use optional **`ca`** (PEM or base64) and **`insecure`** for lab TLS instead.

Microservices and catalog items reference registries by numeric ID or aliases **`remote`** / **`local`**.

[Find out more!](/learn/config/registries) and [Catalog microservices](/learn/config/catalog-microservices).

## Microservice container fields

**`spec.container`** on microservices expands for parity with OCI runtime options:

- Resource limits: **`cpus`**, **`memoryReservation`**, **`memorySwap`**, **`shmSize`**
- Security: **`runAsGroup`**, **`readOnlyRootFilesystem`**, **`capAdd`** / **`capDrop`**
- Devices and mounts: **`devices`**, **`tmpfs`**, **`cdiDevices`**, volume **`scope`** for named volumes
- Process: **`workingDir`**, **`entrypoint`**, **`commands`**, **`ulimits`**, **`sysctls`**

Wasm and alternate runtimes still use **`container.platform`** and **`container.runtime`** with [runtime classes](/learn/config/runtime-classes).

[Find out more!](/learn/workloads/microservices) and [Microservice fields](/reference/yaml/microservice).

## Edgelet v1.1.2

**Edgelet v1.1.2** pairs with **Controller v3.9.2**. Upgrade fleet nodes after you roll the control plane. Default image: **`edgelet:1.1.2`** on your flavor registry. There is no Edgelet API change in this patch.

On an Edgelet control-plane manifest, optional **`spec.auth.issuerCa`** sets **`OIDC_ISSUER_TLS_BASE64_CA`** on the Controller container. The field is redacted in `edgelet controlplane get --manifest`.

A later `install.sh --upgrade` on the host keeps the CLI flavor's Edgelet repository.

Agent YAML changes when you move from v3.8.0:

- Removed: **`deviceScanFrequency`**, **`bluetoothEnabled`**, **`abstractedHardwareEnabled`**
- Use **`edgeGuardFrequency`** when you need hardware attestation ([EdgeGuard](/learn/edgelet-nodes#edgeguard))

Upgrade on a node:

```bash
sudo sh /usr/share/edgelet/install.sh --upgrade --version=v1.1.2
```

Or use **`upgrade agent`** as described in [Upgrade and rollback Edgelet](/learn/edgelet-nodes#upgrade-and-rollback-edgelet).

[Find out more!](/learn/edgelet-nodes), [Edgelet introduction](/learn/edgelet), and [Edgelet management](/get-started/edgelet-nodes/introduction).

## EdgeOps Console

v3.9 still includes editors for AI catalogs, registry **`type`**, and cluster config flows.

Open with <code>{CLI_NAME} view</code> or **`controller.consoleUrl`**.

[Find out more!](/get-started/edgeops-console), [Console features](/get-started/edgeops-console/overview), and [Operate overview](/learn/operate).

## NATS and Router pins

**NATS** wrapper image tag **`2.15.1-1`** rebuilds the wrapper and embedded **[NATS Server 2.15.1](https://github.com/nats-io/nats-server)** with Go 1.26.10. The embedded server version is unchanged. Volume mounts, JWT provisioning, and `NATS_*` settings match v3.9.1.

On Kubernetes, an empty **`services.natsServer.type`** is **ClusterIP**. The non-TLS client port is not published when you omit the type.

**Router** wrapper image tag **`3.9.2`** embeds **Skupper Router 3.5.3** (unchanged from v3.9.1). The wrapper behavior is unchanged.

[Find out more!](/learn/platform-components/nats-server), [Router](/learn/platform-components/router), and [Message bus in Learn](/learn/message-bus).
