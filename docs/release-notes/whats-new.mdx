## Supplemental groups

`container.supplementalGroups` is a list of numeric host group IDs on a microservice. It is separate from `runAsGroup`, which stays the primary GID. A non-root process can join the group that owns a device node without `isPrivileged: true`.

```yaml
container:
  runAsUser: "1000"
  runAsGroup: "1000"
  supplementalGroups:
    - 44
```

| Rule | Behavior |
| ---- | -------- |
| Shape | At most 16 unique whole numbers from 0 through 4294967295. Names, duplicates, negatives, and non-integers are rejected. |
| Stored order | The Controller sorts the ids ascending and returns them in that order. |
| Key omitted on update | The stored list stays. |
| `[]` | Clears the stored list. |
| List changes | That workload is recreated. |

`describe` prints the key, including an empty list, so the next apply matches the Controller. The agent microservice list always includes `supplementalGroups`. `[]` means none.

The Controller adds column `supplemental_groups` on sqlite, mysql, and postgres during startup. Existing microservices start with no extra groups.

See [Microservices](/learn/workloads/microservices#supplemental-groups) and [Microservice fields](/reference/yaml/microservice#supplemental-groups).

## Interactive exec

<CliName /> **v3.9.3** forwards stdin to the remote PTY. Ctrl+C, Ctrl+D, `exit`, and `logout` go to the remote shell. The local session ends when the remote side closes, or when local stdin reaches EOF.

The CLI sends the terminal size when the session starts. On Unix it sends a new size when the window changes. Windows sends the size once.

Edgelet accepts a resize frame after the shell has started: `{"type":"resize","cols":N,"rows":M}`. Columns run from 2 through 4096. Rows run from 1 through 4096. When the shell finishes, remaining output is sent before the close frame.

See [Logs and exec](/learn/workloads/debugging) and [Exec sessions](/learn/edgelet/exec-sessions).

## Embedded auth users

Deleting a built-in user removes the account. You can create a user with that email again. A row left by an earlier soft delete is removed when that email is claimed. The bootstrap admin and the signed-in account cannot be deleted.

See [Identity and sign-in](/get-started/edgeops-console/identity).

## NATS 2.15.2

**NATS** image tag **`2.15.2`** embeds upstream **[NATS Server 2.15.2](https://github.com/nats-io/nats-server/releases/tag/v2.15.2)**. Wrapper `NATS_*` settings are unchanged. Go stays **1.26.10**.

This upstream release fixes auth-callout allowed connection types, a queue-subscription weight amplification, OCSP responses bound to the wrong certificate serial, leafnode ACLs that implicitly allowed `$MQTT.>`, and MQTT OCSP ignoring `ocsp_peer`.

Leafnode ACLs no longer add an implicit allow for `$MQTT.>`. If a leaf relied on that allow, add an explicit MQTT permission before you roll the image.

**Router** image tag **`3.9.3`** still embeds **Skupper Router 3.5.3**. The wrapper behavior is unchanged. The operator image and Helm chart move to **3.9.3** with the same flat values file as chart **3.9.2**.

See [NATS Server](/learn/platform-components/nats-server), [Router](/learn/platform-components/router), and [Kubernetes with Helm](/get-started/deploy/kubernetes-helm).

## Edgelet v1.1.3

**Edgelet v1.1.3** pairs with **Controller v3.9.3**. Upgrade fleet nodes after you roll the control plane. Default image: **`edgelet:1.1.3`** on your flavor registry.

Local deploy and Controller-managed workloads accept `supplementalGroups`. Omitting the field leaves an existing workload unchanged. Changing the list recreates that container. Docker and Podman receive the ids as extra groups. The primary user and group stay as written.

Each published binary ships a CycloneDX file and an SPDX file next to the binary.

Upgrade on a node:

```bash
sudo sh /usr/share/edgelet/install.sh --upgrade --version=v1.1.3
```

Or use **`upgrade agent`** as described in [Upgrade and rollback Edgelet](/learn/edgelet-nodes#upgrade-and-rollback-edgelet).

See [Edgelet nodes](/learn/edgelet-nodes), [Edgelet introduction](/learn/edgelet), and [Edgelet management](/get-started/edgelet-nodes/introduction).

## EdgeOps Console

**EdgeOps Console v1.1.2** ships embedded in the Controller image (default port **8008**). The YAML editor and the microservice detail panel keep **Supplemental Groups** separate from **Run As Group**.

Shell tabs use the remote terminal size. The visible tab owns that size, and a resize updates the session.

Open with <code>{CLI_NAME} view</code> or **`controller.consoleUrl`**.

See [EdgeOps Console](/get-started/edgeops-console), [Console features](/get-started/edgeops-console/overview), and [Workloads](/get-started/edgeops-console/workloads).

## AI Model and Knowledge catalogs

v3.9 adds fleet **`kind: Model`** and **`kind: Knowledge`** resources. The Controller pulls weights or datasets from **`type: hf`** or **`type: oci`** [registries](/learn/config/registries), tracks attach state per Edgelet node, and mounts ready content into microservices.

| Catalog | Purpose | Microservice bind |
| ------- | ------- | ----------------- |
| **Model** | LLM and inference weights (GGUF, safetensors, OCI model-spec) | **`spec.models.items[]`** |
| **Knowledge** | RAG corpora, Hub datasets, OCI document bundles | **`spec.knowledge.items[]`** |

Console path: **Config → AI Model Catalog** and **Config → AI Knowledge Catalog**. CLI: **`deploy`**, **`describe model`**, **`attach model`**, and the matching **`knowledge`** commands.

Edgelet nodes can also hold local **`edgelet.iofog.org/v1`** models for lab workflows. Fleet operators usually use the Controller catalog.

See [AI Model Catalog](/learn/config/ai-model-catalog), [AI Knowledge Catalog](/learn/config/ai-knowledge-catalog), and [Microservices](/learn/workloads/microservices#v39-container-models-and-knowledge).

## Registries (OCI and Hugging Face)

Registry rows declare a backend with **`spec.type`**: **`oci`** (container registries) or **`hf`** (Hugging Face Hub). Private Hub pulls use a token in **`password`**.

v3.9 removes **`requiresCert`**, **`certificate`**, and **`isSecure`**. Use optional **`ca`** (PEM or base64) and **`insecure`** for lab TLS instead.

Microservices and catalog items reference registries by numeric ID or aliases **`remote`** / **`local`**.

See [Registries](/learn/config/registries) and [Catalog microservices](/learn/config/catalog-microservices).

## Microservice container fields

**`spec.container`** on microservices includes OCI runtime options:

- Resource limits: **`cpus`**, **`memoryReservation`**, **`memorySwap`**, **`shmSize`**
- Security: **`runAsGroup`**, **`supplementalGroups`**, **`readOnlyRootFilesystem`**, **`capAdd`** / **`capDrop`**
- Devices and mounts: **`devices`**, **`tmpfs`**, **`cdiDevices`**, volume **`scope`** for named volumes
- Process: **`workingDir`**, **`entrypoint`**, **`commands`**, **`ulimits`**, **`sysctls`**

Wasm and alternate runtimes still use **`container.platform`** and **`container.runtime`** with [runtime classes](/learn/config/runtime-classes).

See [Microservices](/learn/workloads/microservices) and [Microservice fields](/reference/yaml/microservice).
